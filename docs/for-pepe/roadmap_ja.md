## 1. 何が変わり、なぜ計画を変えるのか

17モデルの統制実験と新しい base vs instruct のランで、論文にできる材料は揃った。
ただし結果を**次数保存ヌルモデル**（これまでパイプラインに存在しなかった）で検証し直したところ、
看板の指標が生き残らなかった。

> 各語の入次数・出次数を保ったまま定義グラフの辺をランダムに張り替える。
> カーネルが本物の構造なら、観測カーネル率はこのヌルを明確に上回るはずである。
> **上回らない。** 23モデルで z は −4.2〜+3.0 に散らばり系統的な超過がなく、
> **WordNet 自身も z ≈ 0 である。**

つまり `kernel_ratio` が測っているのは、定義文がどれだけ密に語彙内の語を参照するか
── 定義文の長さと語彙選択 ── であって、概念組織ではない。
これは君がすでに見つけていた r(kernel, out-degree) = +0.798、
kernel_ratio 単独の Q²_loo = −0.17 と整合する。

**しかし補正しても消えないものが一つある。**
相互定義（A を B で定義し、B を A で定義する）は**偶然の9〜24倍**出現し、
その過剰度は instruction-tuned モデルと base モデルを完全に分離する。

| 群 | 相互定義過剰度 *R* |
|---|---|
| Instruction-tuned（17モデル） | **8.9 – 23.5** |
| WordNet（人間の辞書） | **10.0** |
| Base / pretrained（5モデル） | **1.5 – 7.3** |

重なりがない。さらに長さ5以上の閉路は逆向きで、instruct はヌルより**少なく**、
base はヌル並みかそれ以上である。これは Levary et al. (2012) が人間の辞書について
見出した性質そのものである ── 意味のある閉路は短く、長い閉路は意味のずれの兆候。

**これが論文になる。**
「LLMの辞書はスケールとともに人間の辞書に近づく」（偽）ではなく、
「LLMの辞書には偶然を超えた短い循環構造があり、その量は WordNet より多く、
それを作っているのは事前学習の規模ではなく指示チューニングである」。

詳細な分析：[`../research-direction-2026-09.md`](../research-direction-2026-09.md)

## 2. これから守る主張

**タイトル（仮）**
> *Do LLM Dictionaries Close? Density-Corrected Definitional Circularity Shows What
> Instruction Tuning Adds*
> （LLMが書く辞書は閉じるか ── 密度補正した定義循環構造と指示チューニングの寄与）

**三段構成。各段が結果節ひとつに対応する。**

1. **古典的な辞書グラフ指標はヌルモデルを通過しない。**
   Vincent-Lamarre のカーネル／コア／MinSet を LLM生成定義にそのまま適用すると、
   次数保存ヌルと区別のつかない値が出る。WordNet の3,000語部分グラフでも同じである。
   「大きいモデルほど人間の辞書の構造に収束する」という形の主張はすべて定義文長の副産物である。
   *ここには我々自身の過去の主張の訂正も含まれる。それを明記する。
   自己監査する論文は査読者に敬意を持たれるし、同じ反論を先回りして潰せる。*

2. **密度補正後に残る構造は相互定義の過剰である。**
   *R* =（観測2-閉路数）/（次数保存ヌルでの期待2-閉路数）。
   LLM は 8.9〜23.5、WordNet は 10.0。
   密度を補正してもなお、LLMの辞書は人間の辞書より相互再帰的である。

3. **その構造は指示チューニングが作る。スケールではない。**
   同一パラメータ数の Gemma3 pt/it 対が *R* で完全に分離する。
   指示チューニングは知識を足しているのではなく、モデルの規模を語彙的な精緻化に変換している
   （it：サイズとともに定義文長 4.0 → 14.4語。pt：サイズによらず 18〜24語で平坦）。

**主張3についての重要な但し書き。**
現状 base モデルの出力は定義になっていない。12〜18% がプロンプトの逐語エコー、
12〜37% が疑問文である。下記 E2 を終えるまで、pt/it の対比が測っているのは
*フォーマット追従能力*であって構造ではない。主張3を出す前に必ず直すこと。
フィルタ後に分離が消えたなら、それも報告に値する結果である。見つけたものを書く。

## 3. 実験 ── この順序で

各タスクに「何を作るか」「何を出力するか」「**何をもって完了とするか**」を書いた。
飛ばさないこと。E1・E2 は GPU 不要で、以降すべての前提になる。

### E1 ── ヌルモデルの本格実行 · GPU不要 · 半日

`experiments/null_model.py` はすでにある（監査中に私が書いた。短いのでまず読むこと）。

- `R=100` 反復で 23モデル**＋WordNet** を実行。
- `results/null_model.json` に、モデルごとに `kernel_ratio`・`circulation_rate`・
  2-閉路数・長閉路（≥5）数の観測値とヌルの平均／標準偏差、z値、*R* を出力。
- *R* にブートストラップ95%信頼区間を付ける（ヌル反復を再標本化）。

**完了条件**：全モデルに信頼区間付きの *R* があり、base 群と instruct 群の
信頼区間が重なるかどうかを言えること。分単位ではなく時間単位かかる
（密なグラフでの `simple_cycles` が遅い）。バックグラウンドで回すこと。

### E2 ── 非定義出力のフィルタ · GPU不要 · 2日

主張3が立つかどうかを決めるのはこれである。

- `src/quality_filter.py` を書き、各 JSONL レコードを
  `definition` / `prompt_echo` / `question` / `off_topic` / `fragment` に分類する。
  まずルールで（出力にプロンプトの一部が含まれるか、疑問詞で始まるか、3トークン未満か）、
  そのうえで検証する。
- **分類器を手で検証すること。** Gemma3-27B-pt、Gemma3-4B-pt、Gemma3-27B (it)、
  Qwen2.5-0.5B から各100件を抽出し、自分でラベルを付け、クラスごとの適合率・再現率を報告する。
  検証していないフィルタは証拠にならない。
- 現行コードの罠に注意：`generation.py` はプロンプトエコーを `self_referential` と印を付けるが、
  `graph_build.py` は**それをそのままグラフに入れている**。
  結果としてテンプレート語（`use`, `word`, `one`, `short`, `common`, `sentence`）が
  人工的なハブになっている。この経路を直すこと。
- フィルタ後の定義で全グラフを作り直し、E1 を再実行する。

**完了条件**：フィルタ前後の *R* の表と、手ラベルによるフィルタの適合率・再現率を示し、
base/instruct の分離が生き残ったかどうかを率直に述べられること。

### E3 ── base モデルへの few-shot / URIAL プロンプト · GPU 1セッション

**残っている実験のなかで最も価値が高い。**
査読者は必ずこう言う ── base が失敗するのは構造がないからではなく、
応答分布を持っていないからだ（Response Tuning, arXiv:2410.02465）。

- Gemma3 の `-pt` 5サイズに対し、zero-shot の指示文ではなく3例の few-shot 定義プロンプトを与える
  （雛形は `docs/study_guide/ja/04_future_plan/02_experiment_plan.md` にある）。
- それ以外はすべて同一：同じ3,000語リスト、同じシード、同じデコーディング。
- E2 のフィルタを通したうえで *R* を再計算する。

**完了条件**：一つの問いに数値で答えられること ──
base の *R* は instruct の範囲（8.9以上）に入るか、下に留まるか。

- **下に留まるなら**：構造は指示チューニングが作っている。主張3は強い。
- **上がるなら**：構造は事前学習に潜在しており、指示チューニングはそれを引き出しただけ。
  主張3は弱まるが、論文としては**より面白い**。その形で書けばよい。

どちらも結果である。どちらかを期待しないこと。

### E4 ── 定義文長の統制 · GPU 1セッション

*R* が単に冗長さを追っているだけではないか、と必ず訊かれる（Lake et al., NAACL 2025）。

- 二通り。安い方から：
  (a) **事後マッチング** ── 比較するモデル間で出次数分布が揃うように定義をサブサンプリング。GPU不要。
  (b) **プロンプト統制** ── 明示的な語数制約（"in about 12 words"）を付けて再生成し、
      tokens/word をサイズ間で揃える。
- *R* を再計算する。

**完了条件**：長さを揃えた比較での *R* を示し、base/instruct の差が残るかを述べられること。

### E5 ── チャットテンプレートなしでの instruct モデル · GPU 1セッション

テンプレートそのものが構造的効果を生みうる（"The Price of Format", Findings of EMNLP 2025）。
我々の it モデルにはテンプレートが付き、pt モデルには付かない。これは本物の交絡である。

- instruct 3モデル（Gemma3-4B、Gemma3-27B、Qwen2.5-7B あたり）を、
  チャットテンプレートを適用しない生のプロンプト文字列で再実行する。
- *R* を再計算する。

**完了条件**：テンプレートなしでも *R* が高いままかを言えること。

### 予備 ── E1〜E5 を終えてから

| # | 実験 | 目的 |
|---|---|---|
| E6 | 複数シード（42 / 123 / 456） | 全指標にエラーバー |
| E7 | 単語リストのブートストラップ（×20） | 君が見つけた WordNet ベースラインの 15.5% → 8.0% 変動の定量化 |
| E8 | 定義品質の外的軸（WordNet gloss 類似度 / LLM-as-judge） | *R* が「良さ」を測ると言うための唯一の道 |
| E9 | bitsandbytes 量子化 study の再実行（定義文を保存して） | 現在のファイルは bf16/int8/int4 で有効数字15桁まで一致しており、このままでは報告できない |
| E10 | プロンプト変動アブレーション（3種のテンプレート） | Suresh et al. (2023) への回答 |

すでに23モデルあり、信号はスケール軸にはない。
モデルを足しても論文は強くならない。強くするのは上の5つの統制である。

## 4. 統計面の修正

パイプラインではなく解析側のバグ。E1・E2 を回している間に直すこと。

1. **`experiments/regress_model_size.py` が検証指標で選択している。**
   C(6,3) = 20通りの3特徴組合せを全探索し、Q²_loo 最大のものを報告している。
   これでは Q² = 0.71 は楽観バイアスを含む。
   (a) 3特徴を事前登録してそれだけを報告する、または
   (b) ネスト交差検証（内側で選択、外側で評価）にする。
2. **n=5 の相関を小数第3位まで報告している。**
   `docs/paper_ja.md` の r = −0.862 / +0.982 は Qwen3.5 の5点である。
   ブートストラップCIを付けるか、落とす。
3. **多重比較の補正がない。** 複数指標×ファミリー×生／偏を走査して単調なものを取り上げている。
   検定族として報告するときは BH-FDR をかける。
4. `analyse_confound.py` の偏相関の実装は正しい。触らなくてよい。

## 5. 学ぶべきこと（と、その順番）

始める前に全部やる必要はない。それを使うタスクの直前に学べばよい。

### E1 の前 ── ヌルモデルとランダムグラフ

- **次数保存ランダム化／configuration model。**
  なぜ「同じ次数列を持つランダムグラフ」と比較することが、構造が本物だと示す標準的な方法なのか。
  Newman, *Networks* (2nd ed.) 12〜13章。
- **z値とブートストラップ信頼区間。**
  「偶然より多い」を形容詞ではなく数値で言う方法。
- `experiments/null_model.py` を一行ずつ読み、`nx.directed_edge_swap` が
  何を保存し何を壊すのかを自分の言葉で説明できるようにすること。

### E2 の前 ── パイプラインの内部

- `src/graph_build.py`、`src/normalize.py`、`src/generation.py` を通しで読む。
  特に、`status` が `self_referential` のレコードがどう扱われるかを追い、
  プロンプトエコーのテキストが辺になっていることを自分の目で確認すること。
- 自分の分類器の**適合率・再現率**。
  「そのフィルタが正しいとなぜ言えるのか」と必ず訊かれる。答えは手ラベルの標本しかない。

### E3 の前 ── 指示チューニング

- **指示チューニングが実際に何を変えるのか。**
  Lin et al. (2024), URIAL, arXiv:2312.01552 ──
  アライメント後もトークン位置の 77.7% でトップ1トークンは変わらず、変化は文体的である。
  我々の結果は辞書全体のレベルでこれを複雑にする。だから面白い。
- **チャットテンプレート。** `tokenizer.apply_chat_template` が何をするのか、
  なぜ base モデルにはそれがないのか、なぜコミット `ef1c130` でフォールバックが必要になったのか。
- **なぜ base モデルはプロンプトをエコーするのか。**
  Response Tuning, arXiv:2410.02465 ── 能力ではなく、確立された応答分布を欠いている。

## 8. 先に直すリポジトリの問題

小さいが、これがあると他が進まない。

1. **パッケージが壊れている。** `pyproject.toml` は `packages = ["src/rs_dic_llm"]` を宣言しているが、
   整理後にソースは `src/*.py` に移り、`src/rs_dic_llm/` には古い `__pycache__` しか残っていない。

## 9. 進捗の報告のしかた

実験を持ってくるときは、毎回この4つを揃えること。

1. **数値**と、その不確かさ。
2. **何と比較したのか（ヌルまたは統制）** ── 比較のない数値は証拠にならない。
   今回学んだことの全部がこれである。
3. **何が観測されたらその主張を捨てたか。** 捨てる条件を言えないなら、それは検定ではない。
4. **再現するコマンド**と、出力ファイルの場所。

上の計画と矛盾する結果が出たら、それが持ってこられる最も価値のあるものである。早く持ってくること。
